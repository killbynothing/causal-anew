# 情景记忆：时序分桶 × 多筛落位 × 与细剖关系（2026-08-05）

> **性质**：专项规格；**不另起总排期**。总入口仍是 `长期路线图_2026-08-03.md`。  
> **触发**：开场前记忆批量筛查时，常把「开场后才经历 / 后文才写明但时间点在开场后」的场面也捞出来；需统一「放哪、按什么轴、会否与细剖冲突」。  
> **上位**：`深过去记忆×信息不对齐` · `策划_情景记忆装配与执行` · 装配备忘 §3–§4。  
> **状态**：★★★ **等人裁 §6**。未裁不改 schema、不批量挪已入库行。  
> **铁律**：不许编；可审；报账。玩时不回跳原著。细剖≠角色「我记得」。

---

## 0. 结论（先对齐）

1. **主轴是故事内时间（diegetic time），不是「小说第几章写到」**。章号只是近似投影（很多经历后文才写明）。  
2. **多筛出来的不要扔、也不要全标成开场已持有**。仍可进记忆资产管线，但进 **B/C 桶**（开场后默认人生 / 本周目活记忆），开场召回闸看不见。  
3. **与细剖不冲突**：细剖 `events` = 导演脊柱；情景 `slow_memory` = 角色经历版本。可挂 `src_event` 对齐，**禁止**互相当检索主索引。  
4. **玩家影响**：正典 B 桶是「默认会过上的人生」；本周目实际经历进 C 桶（run≥1）并**覆盖/否定**被 δ 搅黄的 B 条。

一句话：**筛宽一点没关系；入库要按「角色什么时候经历」分桶，别按「作者哪章写出来」一锅炖。**

## 1. 三桶（角色记忆侧）

以开场故事时刻为 **T₀**（当前产品：天安门/序幕那一刀；不必纠结等于 Ch几，见 §2）。

| 桶 | 名称 | 角色何时经历 | 筛查时怎么标 | 入库吗 | 召回条件（目标态） |
|---|---|---|---|---|---|
| **A** | 开场前已持有 | 经历时刻 ≤ T₀ | `bucket=A` · `t_diegetic≤T0` | **现在就迁** `slow_memory` run=0 | 开场即可进候选 |
| **B** | 开场后正典默认人生 | 经历时刻 > T₀，且原著正典会发生 | `bucket=B` · `t_diegetic` 或 `t_band` | **可进同一张表** run=0，但**持有闸未到不开**；或先只留筛查稿、后置迁 | 故事时间到了 **且** 本 run 未被 δ 否定 |
| **C** | 本周目活记忆 | 本 run 真发生（玩家在场/离屏结算） | 不靠筛查预写正文 | **玩后固化** run≥1（consolidator / 拍结算） | 仅本 run；盖过冲突的 B |

另两层（不是情景桶，勿混进筛查主表）：

| 层 | 是什么 | 存哪 |
|---|---|---|
| **K** | 知情结论（知不知道、版本） | knowledge / propositions |
| **P0** | 世界拍/因果脊柱 | `events`（导演专用） |

**禁止**：

- 把 B 标成开场已持有（`available_ch` 开到 T₀ 或误用 0/8「一刀切全开」）。  
- 把 P0 `events.action` 整段灌进 A/B 当「我记得」。  
- 因「多筛了」就砍库或删筛查行——**筛查稿宜详；入库闸宜严**。

## 2. 按时间，还是按章节？

### 2.1 主排序键：故事内时间

每条情景记忆在筛查表增加（或等价备注）：

| 字段 | 含义 | 例 |
|---|---|---|
| `t_band` | 粗带（必填） | `childhood` / `teen` / `pre_china_years` / `arrival_eve` / `post_opening_canon` / `endgame_only` |
| `t_diegetic` | 可选精标 | 相对 T₀ 的叙述：「四年前清晨」「到京当夜」「十六中门之后」 |
| `narrated_in` | 作者写到哪 | `novel_*:L…` / Ch.110——**只作出处，不作持有条件** |

**规则**：持有看 `t_diegetic`（相对 T₀）；出处行号只证明「不是编的」。

### 2.2 章号 `available_ch` 是什么

现行列 **`available_ch`** =「从哪一章锚点起，该意识**允许持有**这条记忆」的**工程投影**，不是「这事写在第几章」。

| 用法 | 正确 | 错误 |
|---|---|---|
| A 桶开场竖切 | 统一映射到开场章窗下界（产品现用 `0` 或 `8` 须**全仓择一**，见 §6） | 龙也用 0、修哉用 8 却不说明是否同义 |
| B 桶 | `available_ch` ≈ 该经历在细剖/契约上的**发生章锚**（故事推进到那才持有） | 写成叙述出现章（Ch.110 才写 → 误标 110 才记得，开场前其实已经历则应进 A） |
| 后文才写明的**前史** | `t_band`∈开场前 → **A**；`available_ch`=开场下界 | 因写在 Ch.110 就扔进 B |

**差不多但不相同**：多数主线经历的发生序 ≈ 章序，所以工程上暂用 `ch_anchor` 近似时间轴够用；分叉点是「闪回/后文回溯」——必须以 **经历时** 入桶，不能以 **书写时** 入桶。

### 2.3 T₀ 怎么定（开场竖切）

- **T₀** = 玩家进入可玩开场时，角色「此刻」的故事时间（天安门踱步 / 序幕交坠前那一刀）。  
- 「刚到中国、接风、广场」若故事上**已发生在 T₀ 之前或当下刚发生** → **A**（近前史）。  
- 「十六中门之后、医院、后半部坦白」等 **T₀ 之后** → **B**（即使筛查时从后文捞到了）。

## 3. 多筛出来的放哪？

### 3.1 筛查稿（永远可留）

同一份 `★★★筛查_<角色>_…md` 里分三节即可，**不必另开文件**（除非单人 >80 条再拆）：

```text
## A · 开场前（本次可裁可迁）
## B · 开场后正典（多筛寄存 · 本次不迁或只迁且闸死）
## C · 注明「待玩后固化，不预写」的占位（可选）
```

每条强制：`bucket` + `t_band` + 出处 + 开场可说？  
B 节人裁可以只扫标题：**收/缓/弃**；弃=与正典冲突或非该意识经历。

### 3.2 库里怎么放（推荐默认）

| 选项 | 做法 | 何时用 |
|---|---|---|
| **B1 同表闸死（推荐中期）** | B 进 `slow_memory` run=0，`available_ch`=发生章锚；开场 fetch 因章窗进不来 | 持续世界、离屏也要「到点记得」 |
| **B2 先稿后库（推荐现在）** | B 只留筛查稿；A 才 `--apply` | 开场竖切产能优先；避免误开闸 |
| **B3 平行 staging 表** | 未裁 schema 前不做 | 后置 |

**当前建议（等人裁）**：**新筛查一律分 A/B；迁库默认只迁 A。**  
已误把 B 迁成开场持有的（若审计发现）：改 `available_ch` 拉到发生章，或暂时从开场候选剔除——**单独立项修，不在本计划偷改**。

### 3.3 和「像人一样活着」怎么接

```text
开场可想 ≈ A
章推进且无 δ 搅黄 ≈ A ∪ B(到点)
玩家搅过后 ≈ A ∪ B(未否定) ∪ C(本 run 真经历)
```

B 不是剧透给角色「未来记忆」——是**日子过到那儿之后**才持有的正典默认；C 才是玩家留下的疤。

## 4. 会不会和细剖冲突？

### 4.1 不冲突的分法（写死）

| | 细剖 `events` | 情景 `slow_memory` |
|---|---|---|
| 服务谁 | 导演 / 契约 / 转场 | 该意识召回演戏 |
| 答什么 | 世界线上发生了哪一拍 | 「我」带着情绪记得哪一幕 |
| 粒度 | 原子拍、在场者、因果 | 可合并多拍为一场回忆 |
| 玩家 δ | 改节点达成/脊柱压力 | 改 C；否定对应 B；A 一般不动（除非改写过去类能力——本游戏默认无） |

**同真不同文**：世界真相可以一份；角色 View 可以残缺/装死/误读。细剖有拍 ≠ 每人记得该拍。

### 4.2 对齐方式（可选挂接，非必须）

- 若 B/A 对应某细剖拍：填 `src_event`（或 anchor 脚注 event_uid）。  
- 若纯前史细剖没有：`src_event` 空，**必须**有 `available_ch`/`t_band` + `canon_src` 行号。  
- **冲突裁决**：  
  - 世界事实争议 → **库/`events` 赢**（红线 1）。  
  - 「他开场记不记得」→ **记忆桶 + 人裁 View 赢**，不以细剖有无代替。  
  - 正文与细剖动作矛盾 → 标 ★★★ 停迁，人裁；Agent 不得私自改细剖。

### 4.3 常见假冲突

| 现象 | 实际 |
|---|---|
| 后文 Ch.110 才写童年 | A 桶；不是 B |
| 细剖 Ch.20 有拍，角色开场就记得四年前的事 | A；细剖是后来叙事呈现 |
| 细剖尚未拆到的前史 | 仍可进 A（有原著行号） |
| 玩家没去医院，库里有医院 B | 本 run 不解锁 / δ 否定；不删 run=0 正典行 |

## 5. 批量筛查改规（给外包 AI 的硬约束）

在现有 S1 提示词上追加：

1. 每条必须填 **`bucket∈{A,B}`** + **`t_band`**；拿不准标 `bucket=?` 进「待裁」勿默认 A。  
2. **本次迁库范围写死只 A**；B 进同文档 B 节，标题写「多筛寄存·不迁」。  
3. 判断入桶口诀：  
   - 「开场这一刻，他身体/意识是否已经历过？」→ 是 A / 否 B。  
   - 「只是后文才告诉读者？」→ 仍按经历时，不按书写章。  
4. 双意识：同一世界事件两条 View，桶可以不同（一侧开场前已知、一侧不知）。  
5. 报账增列：`A条数 / B条数 / ?条数`。

S2/S4：只对 **人裁勾选的 A** 写 migrate；B 若走 B1，另批次 + 发生章锚 + 单测「开场 fetch 不含 B」。
