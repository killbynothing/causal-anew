## 0. 结论（先对齐）

**同意你的分法，而且应该升成现行口径：**

| 资产 | 服务谁 | 答什么问题 | 不该干什么 |
|---|---|---|---|
| **细剖 `events`** | **导演**（+契约/转场章窗） | 「这条世界线上，从 Ch1 起剧情怎么推进」 | **不当**角色随身回忆库；不按对白全文搜来演戏 |
| **深过去 / 前史记忆** | **角色意识** | 「开场时，这个人已经带着什么过去」 | 不把未发生的细剖未来灌进开场包 |
| **知情表（谁知道什么）** | **角色 + 披露闸** | 「同一件事，A 知全貌 / B 只知碎片 / C 不知」 | 不把剧透写成每天人设 |
| **本周目固化** | **本 run** | 「玩家刚造成什么、上场刚发生什么」 | 不冒充全书正典前史 |

一句话：**细剖 ≈ 导演看进展；深过去 × 信息不齐 ≈ 角色活着的记忆主粮。**  
开场从 Ch≈0/1 起玩时，角色嘴里能掏出来的「以前的事」，多数是**小说后文才写明、但角色早已经历**的东西——这些必须从后文**蒸馏成开场已持有**的资产，而不是指望 `events` 在 Ch1 里已经写全。

## 1. 问题本质（为什么细剖不够）

1. **时间方向反了**  
   细剖是「故事进行时」的原子拍。深过去是「故事开始前 / 8 章前已发生、后文才被提起」的经历。玩开场时，细剖未来还没发生；角色却已经记得。

2. **真值 ≠ 每人手里的版本**  
   世界真相可以只有一份；角色包必须是**投影**：完整真相 / 半知情 / 误读 / 故意隐瞒 / 只知体感不知因果。复杂在「真相背后」，体验在「接触每个角色时信息不对齐」。

3. **检索对象错了就会假活**  
   「提到就搜 `events`」会把导演账本误当成角色回忆，还容易串线、剧透、把未到章事实搜出来。正确的是：提到 → 在**该意识已持有的深过去/知情子集**里召回 Top-K。

4. **现码也侧面证明了这点**  
   - `events`：565 条，主路径按章给导演态势，不对白检索。  
   - `slow_memory`：33 条且多为孤儿（缺 `available_ch`/`src_event`），开场三人侧几乎装不进包。  
   - 真正像「提到就召回」的，是开场 lorebook 手写关键词——说明需求存在，但还停在场次补丁，没升成库资产。

## 2. 目标态（机器可描述）

对任意在场意识 `cons`、当前章窗 `ch`、玩家/场上话语 `q`：

```text
Recall(cons, ch, q) =
    DeepPast[cons]           # 开场前已持有；available_ch ≤ ch
  ∩ Knows[cons, ch]          # learn_ch ≤ ch；含「只知表面」投影文
  ∪ RunEpisodes[cons, run]   # 本周目固化
  → score(q) Top-K
  → 进 ActorPacket；说出仍过 disclosure / 关系档
```

导演侧另走：

```text
DirectorSpine(ch) = events(run=0) 按章/地点/因果
```

**验收句（人可感）**：同一句追问（例：挂坠从哪来 / 你们怎么认识 / 魏初是谁），秋人、修哉、晴明、龙也给出的**可知范围与说法版本不一致**，且都能在库里指到「持有哪条、缺哪条」，而不是靠卡面散文碰运气。

## 4. 信息不齐怎么建模（最小够用）

每条「事」拆成 **Truth 节点** + **若干 View**：

```text
Truth T   ← 世界侧一句（可后置；先有 View 也能玩）
View V(cons, T) =
    ownership: owns | partial | none
    text_for_actor: 该意识可回忆的说法（可安全投影）
    learn_ch / available_ch
    speak_policy: 可主动提 / 仅被问可答 / 对谁可说 / 绝口不提
    canon_src
```

开场验的不是「库里有没有 T」，而是「接触 cons 时拿到的是不是正确的 V」。

**样板议题（首批只为开场服务 · ★★★ 选题待裁）**：

1. 挂坠从哪来 / 谁交的 / 谁知道交坠这件事  
2. 龙也托付相关（谁知意图 vs 谁只见过挂坠）  
3. 三人行怎么凑到中国 / 魏初接待角色（表面说法 vs 实知）  
4. 秋人·修哉·晴明彼此前史（到开场为止各自以为对方是谁）  
5. 「8 章前」高频被后文提起、但开场就该已存在的经历（按角色列清单，不先铺全书）

## 5. 材料怎么挖（不做编造生产线）

### 5.1 挖掘顺序（对一个角色）

1. 定 `cons` + 开场章窗。  
2. 扫原著：**后文回忆、旁白回溯、对话里「以前…」**——凡「开场前已发生」打标。  
3. 每条写成候选 View：持有者、说法版本、能否主动说、出处行号。  
4. 对照细剖：细剖有则挂 `src_event`；细剖无（纯前史）→ `src_event` 空但 **必须** `available_ch` + `canon_src`。  
5. Agent 自验（装配备忘 §8）→ ★★★ 可审清单 → 你点头 → 迁移。  
6. 报账单列「哪里是 authored / 哪里空着问你」。

### 5.2 细剖的正确用法（收窄）

- 导演：本章有哪些拍、谁在场、因果下一跳。  
- 转场：章窗内离屏补全。  
- **不**作为开场角色「搜过去」的主索引。  
- 若细剖某拍本身就是「回忆闪回场」，可双向挂：闪回拍 ∈ events；回忆内容 ∈ DeepPast View。

### 5.3 lorebook 的归宿

开场 `opening_memory.json` keyed 条目 = **过渡投影**。  
本计划收口目标：同内容入库为 P1/P2 后，lorebook 只保留「尚未入库的临时 keyed」，最终以库召回为准，避免双源漂移。

## 11. 怎么提起记忆（文献对齐 · 2026-08-04）

### 11.1 你的判断对不对

**对。**「细剖/事实记录」≠「带着情绪的记忆」。

认知科学（Tulving 1972）把陈述记忆拆成：

| | **情景记忆 episodic** | **语义记忆 semantic** |
|---|---|---|
| 是什么 | 亲身经历过的具体场面（何时何处、谁、什么感觉） | 脱离时空的事实与概念 |
| 体验 | 可「心理时间旅行」——像又置身那一刻 | 只是「知道」 |
| 在我们项目里 | **角色记忆库**（经历正文 + emo_tag + 感官锚点 + 归属意识） | 知情命题 K.* / 部分 knowledge_schedule |
| 细剖 `events` | ❌ 更像**世界事件账本**（第三人称真值拍），给导演 | 也不是角色语义自传 |

AI Agent 文献同一条线：

- **CoALA / Generative Agents**：情景 = 决策环里留下的经验记录；召回用 recency × relevance × **salience**（含情绪显著），不是纯事实检索。  
- **SYNAPSE / MNEMA 等**：情景与语义分库；巩固（consolidation）才从经历蒸馏出抽象事实——不是反过来拿账本冒充回忆。  
- 本仓旧设计「慢环 = 感官锚点 × cos+emo」正是情景召回，不是 events RAG。

### 11.2 运行时要不要「搜记忆库 → 再跳原著」？

**不要跳原著。**

| 阶段 | 读什么 |
|---|---|
| **入库/蒸馏（作者时）** | 原著 + 自述章 + 他人转述 → 写成**带情绪的经历条目**，挂 `canon_src` 行号 |
| **玩时召回** | 只搜该 `cons` 的记忆库 Top-K（cue / cos+emo / 显著性）→ 进 ActorPacket |
| **导演看进展** | 另通道读 `events` 章窗——**不进**角色「我记得」槽 |

理由：原著是叙事全文，不是「某人第一人称、已门控、已带情绪标签」的记忆对象；玩时回跳会剧透、串意识、把未持有事实搜出来，也和「知≠说」闸冲突。

### 11.3 我们怎么提起记忆（目标规程）

```text
cue(q, scene, affect_now)
  → candidates = MemoryStore[cons] ∩ available_ch≤ch ∩ ownership
  → score = α·similarity(q, text+anchor) + β·emo_match + γ·salience
  → Top-K episodic lines → packet「想起…」
  → 说出仍过 disclosure / 装死危险闸 / 关系档
```

- **记忆库宜详**：人的根本在经历，不在人格核短条；token 压力用 Top-K 与门控解决，**不靠砍底库**。  
- **情绪是一等公民**：条目必有 emo/锚点；否则退化成事实卡片。  
- **双魂分册**：同一 Truth 两份 View（实行 vs 目睹/跃迁者）。
