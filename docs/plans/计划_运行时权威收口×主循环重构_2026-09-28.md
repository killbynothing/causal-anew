### 1.2 什么不应误判成“双权威”

- 库中 PersonaCore/RelBaseline 与 run 内 ActorMind 是种子与演化态，不能为了统一删掉种子。
- EventReceipt 是世界事实的证据，BeatState 是进度投影；branch/ledger 可以保留为只读索引。
- FSM 的披露级别、BodyFrame 的姿态、observer 摘要有各自用途。**禁止的是同一事实被多处独立裁决，不是禁止多种表示。**
- ContextAssembler 是装配者，不是第六套知识真值；现有 KGE/时序/披露闸继续有效。
- Resolver 这个确定性职责可复用 `director_ports.resolve_public_action`；函数位于 director 文件不代表 LLM 导演拥有事实裁决权。

## 2. 五域唯一权威合同

这里的“世界事实”指本 run 中什么已发生；正典、Seed 和约束仍以 `world_truth.db` 为唯一真值。不得把运行时 receipt 反写成 run=0 正典。

| 权威 | 唯一可提交的状态 | 输入与读者 | 严禁越权 |
|---|---|---|---|
| World / Resolver | 公共事件、位置/物态、item custody、事实关系 | 经验证的 PlayerAction/Actor/World proposal → EventReceipt → 世界投影 | 编心理；从 NPC 散文推定玩家同意；另造库外正典 |
| PlayerActionResolver | 玩家明确选择/行为及其输入证据；产 PlayerActionReceipt | 原始输入 ID、公开/私有通道、目标、明确度；供 World/Beat/Exit 读取 | 再独立写一份 custody；把心想当公开行为；把 LLM 解释当事实 |
| BeatReducer / BeatState | storylet 实例中节拍的阶段与满足情况 | 只消费已提交证据；completed 为兼容投影 | 补台词、改物件、替玩家接受、直接 EndRun |
| ActorMindReducer | 意识自己的持续 appraisal/goals/commitments/动态关系 | 该意识能观察的 receipt + 既有人裁 seed；FSM/Rel 输出只读投影 | 写世界事实；改人格底色；获知不在场/跨周目秘密 |
| ExitPolicy | continue / transition / end_run 的授权、目标与理由 | 世界/Beat 快照 + exit request + 合同；交生命周期提交器执行 | 因 MH 齐直接结束；自己改 MH/角色/物件；漏过固定前置条件 |

**唯一入口不要求五个巨型类。** 每域可以有纯函数/子 reducer，但外部只拿不可变快照，不能拿共享 mutable session。Exit 的提交器只执行已授权决定，不再判断“该不该结束”。World 的 BodyReducer 只消费同一 event batch，不再从散文独立定归属。

### 2.1 每个持久字段都要有身份和寿命

- 运行范围至少区分 `worldline / run / ch_anchor / session_id / scene_instance_id`；scene_id 不是场实例 ID，同一场可能重访/闪回。
- 心理和情景记忆绑定 `cons_id`；身体、持物绑定 `body_id/item_id`，occupancy/fronting 仍按既有合同选意识。
- `active_goals` 区分场目标与持续承诺；scene leave 不能清掉持续承诺，也不能让旧场临时目标永久回灌。
- 只读 projection 必须带来源 receipt/revision；observer 或保存旧字段不能成为反向写入口。

### 2.2 World 收口必须覆盖的字段

P0 清点至少包括：`completed`、`completed_by_card`、`completed_beats`、`canon_performance_state`、`branch_progress`、`scene_receipts`、`world_transactions`、`causal_receipts`、`run_observation_ledger`、`player_state`、`body_frames`、`world_cursor`、offscreen 状态、`private_inner_states`、`prior_reflect_by_cons`、`actor_minds`、`fsm_by_cons`、`rel_state_by_cons`、`ended`、`_run_closed`、`run_receipt`、δ/settlement。

同一语义可能不同字段保存，也可能有 dict/list 别名。扫描不能只找 `self.completed.append`：必须识别赋值、下标赋值、append/extend/update/setdefault、helper 传引用、load/reset/flashback/skip/CLI/服务旁路及数据库 DML。

## 3. 收据协议与提交边界（目标规格，尚未实现）

### 3.1 扩展现有协议，不平行造第二套总线

复用 `runtime/causal_protocol.py` 的 ObservationFrame / ActionProposal / WorldEvent / EventReceipt，以及已有 `director_ports`、`RuntimeStore`、`SessionDomainState`。按兼容升级补下列字段；P0b 先写样例/schema/迁移测试，不先建通用事件框架。

| 合同 | 必要字段/语义 |
|---|---|
| 公共 envelope | schema_version、receipt_id、request_id、turn_id、sequence、scope（三轴/场实例）、producer、source_refs、visibility、base_revision |
| PlayerActionReceipt | input_id、channel、verb、target、evidence_span、resolution=explicit/ambiguous/rejected；只证明玩家自己表达/执行的动作 |
| EventReceipt | proposal/source receipt IDs、preconditions、outcome、committed effects、policy_version；提议与事实分开 |
| Beat transition | beat_id、before/after、evidence_receipt_ids、satisfaction；不另落世界事实 |
| Mind update | owner_cons、observed_receipt_ids、allowed facet delta、reason_code；禁止自由文本直接成为长期事实 |
| ExitDecision/Receipt | continue/transition/end_run、target、trigger_receipt_ids、requirements_result、reason_code、commit_status |

现有 observation/decision/receipt 标识未统一覆盖 run、场实例与重试边界：`causal_protocol.py:86` 的 observation ID 用场/拍/角色，`:117` 的 receipt ID 则派生自 decision ID（free_stage `:9375/9432`）。新键统一覆盖作用域和 sequence。幂等规则是**同键同 payload 返回已有结果；同键不同 payload 报 conflict**，不能简单 False 后继续改其他投影。边界验证还要检查 actor/scene/run 归属、证据可见性、时序和事件是否已提交。

LLM 可以解释意图、提出动作和心理变化，但不能自行签发已发生收据。模糊输入留 ambiguous，不自动升级接受；普通聊天先记“谁实际说了什么”，不能把说出的陈述一律当客观世界真相。

### 3.2 一拍只有一个生产提交路径

1. 接收 input/request，识别重复与失效 revision；保存可审的原输入通道。
2. 确定性解析玩家自有行动；验证其物理/知识/正典前置条件，生成输入阶段 receipt batch。
3. 从已提交状态给导演/各角色分配不同可见切片；导演提机会，经 Resolver 合法化后才能进角色观察。
4. Actor 产生 ParticipationIntent；Floor 发 FloorGrant；获得机会后 Actor 演绎。
5. 输出先走 player agency、知识、身体连续、四支柱/never_soften 等确定性闸；修复/拒绝的原输出不能成为事实。
6. 仅为本次准备交付的输出段提交 delivery batch；World/Beat/Mind 按同批证据归约。未出队内容不落“已说过”。Reflect 可延后，但只基于已提交且自己可见的 receipt。
7. ExitPolicy 使用本次归约后的快照，产唯一决定；生命周期提交器执行，再持久化可重试的 response/observer 投影并返回。

一拍可有多个有序提交点，但只能调用同一个提交入口；每次 `advance_utterance` 的交付也经过 World/Beat/Mind/Exit。这里 delivered 指服务端已持久化交付记录及可重试的公开响应，不声称浏览器已收到或人已读；网络中断时重取同一 delivery ID，不生成新事实。

流式队列必须区分 generated、queued、delivered、cancelled。**尚未提交交付的台词不能证明“已说过”；barge-in 取消的后半段不得提前完成 MH 或托付。** 用 stream_generation 防旧结果回写新场/新拍；取消只影响未交付段。心想 early return 仍需要自己的私有 receipt，但不进入 NPC 公共观察。

### 3.3 崩溃、并发与外部写入

- 同 session 的 load→reduce→commit 必须串行；同 run 的 close 还需 run 级保护，不能只依赖 JSON 写锁。第一版保持单机实现，不引入消息队列服务。
- 加 revision/CAS 或等效拒旧机制；JSON 使用临时文件+原子替换，坏存档明确报错/恢复原件，不能默当新局。
- P0b 明确“已提交 receipt 的耐久边界”和恢复游标；JSON、δ DB、settlement 不是天然同一事务。未选定单一提交记录及 pending/ack 重试协议前，不声称端到端原子性。
- 推荐在既有 RuntimeStore 上增加有版本的 pending commit/outbox 记录，DB writer 以稳定键幂等提交；它是待投递事务记录，不是另一套世界真值。具体落盘位置/唯一键在 P0b 决定并用崩溃测试证明，涉及表结构仍走既有 import/迁移通道及 diff 审核。
- 输入结果、收据、派生状态和退出决定不能一部分成功却向用户报“全部完成”。关局失败保持可恢复 closing/pending，重试同 batch，不再次生成模型输出/重复沉淀。
- 输入、输出交付、Exit 可以分批依次提交；后批失败不倒销前批已经生效的玩家行动。恢复游标必须指明最后已提交 batch 与待重试 batch，回应明确当前进度。
- shadow 只在冻结快照与已有模型结果上跑纯计算：无 LLM 重调、无 DB/δ/存档写、无实际转场。每一域任何时刻只有一个生产 writer。

## 4. BeatState 与玩家行动的具体语义

### 4.1 不强迫每个 MH 都三阶段

简单事实使用 pending→satisfied；交互节拍使用 open/offered→resolved，并单列 `satisfaction`。**互动已回应，不等于正典固定事实已经满足。** `completed` 只从相应合同的 satisfaction 投影，不能把所有 resolved 都投成完成。

挂坠先分离三条轴：

| 轴 | 状态与证据 |
|---|---|
| 赠与机会 | 未提出 / 已明确口头赠与且可见递出；不等于转移归属 |
| 玩家回应 | 未回应 / 模糊 / 接受 / 拒绝 / 暂放；要有对应输入 receipt |
| 世界物态 | 当前 owner、holder/location；只有成功 EventReceipt 才改变 |

`deferred` 表示本次回应暂放，不默认为永久终局，也不自动取得物件。新动作能否重新开启 offer、拒绝后何时可再提，由合法新事件和已裁场合同决定，不能循环催促。当前单 `ryuya_pendant_disposition` 终局 transaction 在 P2 迁移时必须显式处理。

### 4.2 行动权并不等于世界只能在玩家同意后变化

玩家承诺、接受、主动移动等自有选择必须由 PlayerActionReceipt 证明。外界依法发生的物理影响可以由 WorldEvent 证明，例如已裁世界事件改变位置/伤势；但不能伪造“玩家同意”，且必须通过物理/正典/固定底闸。**不能把外力事件当作绕过拒绝的万能借口。**

物件的 offer、放在桌上、占有、所有权、佩戴各有语义。NPC 自己松手可以改变 NPC holding，但不能由此推得玩家持有。BodyFrame、player.body_props、transaction、ledger、BeatState 必须来自同批事实；一个冲突整批拒绝或显式降级，不能各写各的。

## 5. ★★★ 挂坠固定事实粒度：保留裁决，不改库

**不代裁 tier/canon_locked/never_soften，也不把 RP4 自动升级为固定底。** AGENTS 的固定底专指因果线收束；库中固定因果依赖与挂坠事件有关，不能反过来断言挂坠与固定底无关。

## 6. 实施顺序与每个 loop 的通用门槛

```text
P0a 测绘/测试基线 → P0b 最小收据/存档/提交合同
  → P1a Exit 决策 → P1b 关局恢复与运行生命周期
  → P2a World 提交入口 → P2b 咖啡馆竖切 → P2c 全写路径收口
  → P3 持续心理 → P4 参与意图 → P5 装配入口
  → P6a 场策略外移 → P6b 主循环拆解
  → 咖啡馆 + 天安门完整人验 → 再开高阶能力
```

P0b 前移 Packet 来源和版本合同；P5 仍负责真正搬迁装配实现。P2 必须补足 World 权威，不能只完成 Beat/PlayerAgency 就宣称五权齐备。P3/P4 默认不增加每角色额外模型调用。

每 loop 都必须写：目标不变量、允许改的域、writer 清单、输入/输出协议、迁移/回滚、必跑集、做/验负责人。一个 `loop/<名>` 分支；分阶段提交，quick 绿才可 squash 合 main。子任务只读审计可以同一 loop，独立写代码的并行 loop 用隔离 worktree。**旧 writer 的删除先出清单人审**；代码改造授权不等于删除历史数据授权。

## 8. P1：ExitPolicy 与生命周期

### P1a · 统一决定，贯穿目标

**范围**：`step / skip_scene / _maybe_transition / run_session / flashback return / canonical transition / placeholder end`；所有入口只提交 ExitRequest，单一 ExitPolicy 产决定。

**前置兼容桥**：P1 早于 P2，先从已审 legacy 只读快照和原输入引用构造 ExitRequest，标明 legacy 来源，不补造历史 EventReceipt。P2c 改为消费新已提交 receipt 并撤桥；任何阶段都只有 ExitPolicy 决定出口。

- 判定顺序：候选来源汇集 → 目标解析 → 最终前置条件/固定底闸 → 授权。pending/menu/semantic 不得覆盖最后一道闸。
- 该决定携带具体 target；提交时不再重新 choose_exit_spec。
- 默认 `auto_end_on_complete=false`。纯过场只能按已声明合同显式启用，不能因缺 exits 推断为纯过场。
- 社交场结束需明确离场语义、合法物理离场事件或已裁世界强制条件；MH 仅影响 eligibility。
- skip 不补造玩家行为和 MH 证据；若产品需要“演完再跳”，必须真实提交合法事件或返回尚不可跳。

**必测**：MH 齐但无 exit 继续；独立咖啡馆无 pending_entry 不崩；真正闪回返回原场且不 EndRun；有效自动过场；未满足出口不被确认绕过；审核/执行目标一致；CLI 与 API 同结果。

**P1a 实施结果（2026-09-29）**：

- 新增纯决策模块 `runtime/exit_policy.py`：`ExitRequest → ExitDecision`，Decision 直接携带最终 `exit_spec / target_kind / target_ref / mode`；模块不持 session、不写世界、不保存。
- `step / _maybe_transition / skip_scene / run_session / flashback return / placeholder end` 已收进同一退出授权路径。生产提交阶段消费 Decision 的具体 target，不再二次 `choose_exit_spec`；`run_session` 删除“源卡 MH 全齐就事后补 `ended=True`”旁路。
- 通用 `step()` 删除“MH 齐 + 无 exits ⇒ EndRun”规则；默认完成只改变 eligibility。需要自动终局时必须显式 `auto_end_on_complete` 或经过当前 legacy placeholder bridge 构造一个显式 auto-end Request。后者仍是兼容桥，不升格为新卡正典。
- semantic exit 的 `semantic_receipt` 改为 prospective fact：可参与同一 Decision 的前置条件审核，但**授权前不写 `scene_receipts/branch_progress`**；Decision 授权后才落现有 receipt，避免“申请退出先制造自己的门票”。
- forced-exit 一拍确认现在持久化第一次审核过的 `_last_exit_intent_exit_spec`；下一拍只能确认/取消同一个目标，不重新按新文本选路。卡声明的 `intent_tokens` 与全局离场词统一参与 forced confirmation；多出口只说“我走了”会先出 menu，不能冻结 `exits[0]`。

### P1b · close 失败、reset、副本、并发

**目标状态机**：open → closing → closed；`ended` 为外部兼容投影。可见场结束与 run 结算状态分开，不能用一个布尔假装所有存储完成。

- close 决定有稳定键；DB 失败保留 pending，load/retry 继续同一提交；closed 的 step 返回原收据，不再生成事件。
- reset 不能恢复已关闭 run 的写权；练习视图与可写运行分开。真正新局登记新 run，恢复错误沿已有人裁 fork 流程。
- save_as 保留 run 的副本默认不可形成第二个独立 writer；若要续玩分叉，走显式 fork 记录，不改原 run 历史。
- 同 run 并发 close 在一个受保护提交边界检查/写入。修复 `settle` 的 delete-and-reinsert 债：目标为只追加结算/撤销事件及可重建投影，不借“幂等”删除历史。
- 现有 `run_meta UPDATE`、`revoked UPDATE` 的生命周期投影与严格只追加规则存在口径/实现债，列字段级差异和迁移方案；未经审核不得扩大例外或修改历史行。

**必测**：close/save 各失败一次后恢复；重复请求、并发 close、同 run 两副本；reset/load 不复活闭局写权；固定底拒绝仍有效；沉淀不重复、不删除历史。全部临时 DB。

**降级**：决策已收口而持久化未完成时保留“待结算”状态；不能报成功或把旧自动 EndRun 作为兜底。P1b 未过，P1 不算收尾。

## 10. P3：ActorMind 真正接管持续心理

4. Reflect 是 proposal，经过字段/来源/范围验证后才能形成 MindReceipt；既有一句“必须交付”不再有独立权力。需持久的总结也是派生说明，不是第二套脑。
5. FSM 的披露档由 Mind/既有门控导出；RelState 动态 facet 收到 Mind，RelBaseline 留 Seed。沉默、不获 floor、换场都不能重置持续状态。

**必测**：普通聊天能更新允许的 facet；同 receipt 只应用一次；看不见的事件不改变该角色；不同意识/世界线/周目隔离；两拍沉默后仍保留状态；跨场持续承诺保留、场目标更新；篡改缓存不改变权威、可从 Mind 重建。有证据且行为已认可的旧快照迁移保持结构化状态和下一拍约束等价；冲突/无来源字段给差异报告与恢复策略，不复现旧错误行为。

**降级**：无法证明来源的旧心理字段仅保存在 legacy 审计附件，不继续驱动行为；不重写 PersonaCore。未迁 facet 不允许新旧同时更新。

## 11. P4：Actor 决定参与，Floor 只仲裁

正式区分 `ParticipationIntent`（角色愿意做什么）、`FloorGrant`（获得什么机会）、`ActorEnactment`（实际说/做）。所有在场意识先做轻量 deliberation；第一版可由自己的 Mind/合法观察/社交义务确定性计算，不要求每人额外一次 LLM。

Floor 只读 actor_id、mode、urgency、addressee、公开义务、最近占用/公平性及 lane。**拿不到 MH/goal 文案、导演期望台词、玩家私有心想。** 内容相关性可以影响角色自己的意图，不能由 Floor 再按“谁能推进剧情”加分。

pass、沉默、动作回应、backchannel、side 都是合法结果；被裁掉的 speak 保留 concern，不算失败。单角色场也不能强迫角色说；既有 adjacency obligation 可以要求回应资格，不规定答应或具体台词。明确 Grant 与实际输出不一致的规范化/拒绝规则。

**必测**：公开输入相同、只改 thought，不改变 NPC 可见信息/参与资格；改导演 MH 目标不直接改 Actor intent；Mind 不同可给不同 intent；多人点名/打断/侧聊/公平性；pass 无兜底台词；取消队列不预记台词事实。

**性能**：记录同夹具每拍模型调用数和延迟分布；默认不增加无关角色 LLM 调用。不能用全员发言换“自主”指标。

## 12. P5：ContextAssembler 接管真实装配

从生产路径上的 observe_only 包装升级为唯一装配 owner；搬 `build_actor_context_packet` 的取库/分层/检索/裁剪职责。对既有 `actor_packet_for_prompt` 的保密剥离保持等价，不能把 observer 候选记忆也喂模型。

| 层 | 唯一来源 |
|---|---|
| stable identity | 已裁 Seed / PersonaCore / RelBaseline / ActProfile |
| authoritative present | WorldSnapshot + MindSnapshot + 门控/FSM 派生视图 |
| scene window | 当前意识可见、实际公开的观察与对话 |
| goal-conditioned memory | 当前 Mind 目标驱动检索，Seed/本 run 记忆按时序、披露筛选 |
| scene overlay | 只加本场约束与机会，不覆写人格/玩家事实 |

DB schedule/KGE 决定可知范围；card overlay 不能解锁被锁知识；disclosure 决定能否说。统一来源不等于取消这些不同职责。

**必测**：捕获真实 caller 的最终序列化请求；assembly receipt 的版本/来源/摘要与该请求同源。覆盖正常、opening、repair、autonomous、fallback 等调用，后加 prompt 不得绕门控。withheld/candidate、其他角色私密、跨周目记忆零泄漏；关闭 observer 不影响任何生产结果。

**降级**：assembler adapter 可暂留旧 import，但旧 builder 不能并行取库/重新改包。P0/P3 已定的来源合同不在搬迁时重裁。

## 13. P6：最后拆主循环与场策略

**P6a**：将咖啡馆、天安门、十六中、正典自动段/闪回的策略迁为纯 ScenePolicy。输入不可变快照，输出机会/证据/提议；不持 session 引用、不保存、不关局、不直接改任何权威状态。

**P6b**：`TurnEngine` 只排 input→observe→deliberate→floor→enact→resolve→commit→exit→project。`FreeStageSession` 留 API facade/state handle；存取复用 RuntimeStore/domain envelope；observer/保存是投影适配。

建议职责模块可在现有平铺 runtime 内先落地：`turn_engine`、`exit_policy`、`beat_state`、`player_action`、`world_commit`、`scene_policies`；稳定后再考虑 engine/actors/storylets 子目录。现有 causal_protocol/actor_mind/director_harness/context_assembly 不平行复制。不得为目录漂亮同时修改所有 import。

**验收**：core 不导入具体 ScenePolicy，不含场 ID/专名/内容判据；不是只用敏感词扫描，另验依赖方向和可变引用。咖啡馆 policy 改动只改变咖啡馆 fixture；其它场 projection 不变；CLI/API/话轮队列/存档/回执端到端合同一致。

**降级**：一次一个 policy 迁移并对比已认可结果；旧 facade 可以存在但不得再承载业务 writer。取消未经验证的 LOC 目标，不以拆成多少文件验收。
