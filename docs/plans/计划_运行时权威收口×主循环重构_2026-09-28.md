# 计划：运行时权威收口 × 主循环重构 · 2026-09-28

> **性质**：现行专项重构计划，挂长期路线图阶段 5「人验 + 观测台」；不另起总排期。
> **目标**：不是再补一个功能，而是把现有正确机制重新接成一条有唯一权威、可审计、可迁移的运行时主循环。
> **大改权限**：允许拆模块、删兼容路径、迁移状态结构、重写 FreeStage 主循环、重做测试边界；但仍受 AGENTS 全局红线约束：run=0 只读、run≥1 只追加、never_soften 不松、内容不编、★★★ 创意裁决必须人裁。
> **为什么现在做**：a14 真人咖啡馆连续暴露的三个问题（假断线、RP 齐自动 EndRun、托付/挂坠节拍抢跑）不是三处偶发 bug，而是同一类架构债：多个模块同时在解释“这件事是否发生 / 角色现在想什么 / 玩家是否已经做了某事 / 场景是否应该结束”。

---

## 0. 总体判断

### 0.1 项目方向没有错，运行时边界已经糊了

北极星仍然正确：

> **造一个持续存在的世界：角色会记忆、会判断、会主动行动，并彼此影响。机制服务于角色活着，不是目的本身。**

现仓最有价值的东西也仍然成立：

- `world_truth.db` 唯一真值源；
- 角色与导演分离；
- Director 四端口 + 闭集招；
- ActorPacket 隔离；
- 知识/记忆分层；
- BodyFrame、话轮流、Thought Delta；
- run / δ / EndRun / sediment / scar；
- 确定性 hard gate 优先于 LLM；
- badcase → 归因 → 回归测试 的开发方法。

**问题不在这些原则，而在它们的生产接线。**

现在的 `runtime/free_stage_prototype.py` 已约 13.5k 行；`FreeStageSession` 约 5k 行；单个 `step()` 约 1.8k 行。输入解析、环境响应、正典段、角色自主决定、导演、ActorPacket、speaker plan、MH 会计、BodyFrame、修复器、转场、EndRun、观测台投影都在同一条主路径里彼此读写。

结果是：

> 单个机制各自“对”，组合以后却可能互相替别人做决定。

a14 的三层红灯正是这一点的实证。

## 1. 我们真正想要的系统

理想的一拍不是“一个大函数把剧情推完”，而是五个权威按顺序交接：

```text
玩家公开言行 / 私有心想
        │
        ▼
① Observation
   只整理“谁能看见什么”
        │
        ├──────────────► Director 看公共世界 + 私有导演账
        │
        └──────────────► Actor_i 只看自己的 ActorPacket
        ▼
② Deliberation
   每个 Actor 自己决定参与意愿 / 顶格 concern / 可选动作
        │
        ▼
③ Arbitration
   Floor 只裁谁获得发言/行动机会
   Director 只裁世界机会
        │
        ▼
④ Enactment
   Actor 自己说 / 做
   Stage / Voice 只演已合法的世界变化
        │
        ▼
⑤ Resolution
   Resolver 根据“真正发生的可见事实”落 EventReceipt
        │
        ├──► World state / item custody / branch fact
        ├──► Beat state
        ├──► ActorMind update
        └──► Exit eligibility
```

### 五种权只允许一个入口

| 权威 | 唯一负责 | 不允许负责 |
|---|---|---|
| **World / Resolver** | 什么事实真正成立、物件归属、世界事件、receipt | 写角色心理、替玩家行动 |
| **ActorMind** | 角色自己的持续 appraisal / motive / commitment / relation state | 改世界事实、替别的角色想 |
| **Beat Resolver** | Storylet/MH 当前阶段，只从 evidence/receipt 推导 | 指定台词、指定玩家行为、自动关局 |
| **Player Agency** | 玩家是否答应、拿取、拒绝、离场 | 被 NPC stage 或系统自动补写 |
| **Exit Policy** | 是否允许/执行转场或 EndRun | 把 MH complete 直接等同于结束 |

导演是**世界机会管理器**，不是第六种权威。它不持有角色命运，也不替 Resolver 记账。

## 2. 现在已经有的，与目标的差异

### 2.1 ActorMind：名义权威已经有，实际权威未收口

已有：

- `runtime/actor_mind.py` 是 receipt-driven、结构化、无自由文本 CoT 的正确方向；
- 观测台已显示 `actor_state.authority=actor_mind`；
- autonomous decision 已经能走 `Observation → Proposal → WorldEvent → EventReceipt → ActorMind`。

差距：

- `private_inner_states` 仍持久化、仍被保存/加载、仍进 ActorPacket；
- `want_now`、pending concern、appraisal 等大量运行变化仍直接写 `private_inner_states`；
- session FSM / RelState 又形成并行状态；
- Reflect 多数只是规则生成的一句私有总结，下一拍再塞回 prompt，不是 ActorMind reducer 的真正状态变化；
- 普通聊天没有统一 receipt，因此 ActorMind 很多时候只是“挂着的权威牌子”。

**判断**：ActorMind 是正确骨架，但目前只在部分路径拥有实权。

---

### 2.2 Actor Decide：已有 concern 和话轮，但“要不要说”仍未完全归角色

设计宪法已经写明：

> 每个在场意识先做自主决定（speak / backchannel / side / pass），Floor 与内容分离。

现码：

- `build_speaker_plan()` 先做 bidding，决定 performance_plan；
- ActorPacket 随后被写入 `participation_mode` / `response_slot`；
- `call_actor_packet()` 要求模型的 participation_mode 与 contract 一致。

因此目前更接近：

> 系统先决定“你这拍是主说/次说/短接/动作位”，角色再决定“怎么说”。

而目标应是：

> 角色先表达 participation intent，Floor manager 再解决冲突与顺序。

直接点名 / adjacency obligation 仍可以构成**发言义务或强资格**，但不能变成内容脚本。

---

### 2.3 Director 四端口：原则正确，生产主循环仍被大量旁路

已有：

- `director_ports.py` 的 Stage / Resolver / Dramaturgy / Voice 职责分离正确；
- `director_harness.py` 的闭集招、先裁后填正确；
- 主卡台词已从导演侧卸掉。

差距：

- 世界事实、MH、branch、item transaction、transition 等仍有大量直接逻辑散在 `step()`；
- 并不是所有“事实发生”都必须经过同一种 EventReceipt；
- 因此 Resolver 还不是世界变化的绝对单入口。

**判断**：四端口是对的，但目前更像“部分接线的宪法层”，不是整个世界运行时真正的总线。

---

### 2.4 Beat / Must-Happen：从“脚本”转向“收据”只完成了一半

正确方向已经形成：

- `beat_evidence.py` 用确定性证据；
- 最近人验已经去掉 RP2 的纯拍数证明；
- RP3 改为只认龙也真正说出口；
- RP4 正在拆“赠与提出”和“玩家处分”。

但 `completed: list[str]` 仍然承担太多含义：

- 事实是否说过；
- 剧情是否推进；
- Actor concern 应该切哪档；
- Exit 是否可用；
- 某些地方甚至曾直接触发 EndRun。

一个 boolean 被迫表达一个事件的多个阶段，会不断产生“抢跑”。

**目标**：关键 MH 支持最小阶段态，而不是所有东西只有 done / not-done。

推荐最小模型：

```text
UNSEEN
  ↓ evidence
OPEN / OFFERED
  ↓ counterparty response / resolver receipt
SETTLED
```

不是所有 MH 都要三段，只有交互性强的节点使用。

挂坠就是样板：

```text
UNSEEN
→ OFFERED（龙也明确口头赠与 + 可见递出）
→ SETTLED_ACCEPTED / SETTLED_DECLINED / SETTLED_DEFERRED
```

`RP4=true` 只是最终投影，不再是唯一内部状态。

---

### 2.5 Player Agency：最近补了硬闸，但应该成为全局协议

a14 已经证明：

- NPC stage 可以写出“塞进你手里”；
- 模糊玩家台词可能被 disposition 误判为 accepted；
- 卡里的“必交”又会持续给演员施压。

最近加的挂坠修复器有效，但它仍是**单场特例**。

目标：

> 任何涉及改变玩家身体、持物、位置、承诺、关系选择的结果，都必须有 PlayerActionReceipt 或确定性玩家输入证据。

全局需要保护的不是“挂坠”这个词，而是：

- 玩家收下 / 拒绝物品；
- 玩家移动 / 被带走；
- 玩家答应 / 立誓；
- 玩家同意关系或阵营；
- NPC 替玩家说话；
- NPC 替玩家完成关键动作。

---

### 2.6 Exit：现在仍存在“MH complete → 自动结束”的泛化风险

虽然咖啡序幕已经特判修正，但主循环里仍存在类似：

`all_must_happen_complete(...) && not exits -> _mark_ended()`

这代表旧观念还在：

> “该发生的都发生了 = 场景应该结束。”

目标应改成：

> **MH 只改变 exit eligibility；结束一定由 ExitPolicy 明确决定。**

建议默认：

- `auto_end_on_complete = false`
- 只有显式卡声明的纯过场 / 无自由交互节点可开 true；
- 人物社交场必须由离场语义、物理离场事件、或显式世界强制条件结束。

---

### 2.7 Card：本应是薄 overlay，现在部分内容在替角色脑子下命令

龙也卡当前同时存在两种相反合同：

运行时新合同：

> 玩家可以收 / 拒 / 暂放；未明确表态不能替玩家接。

卡内旧内容：

- “今夜必须当面交到对方手里”
- “挂坠是礼物且必交”
- “RP3 之后必须推进到交付”
- “今夜一定要交到对方手里”

这会让 ActorPacket 自己持续收到“必须塞成功”的压力，运行时却在后面踩刹车。

**原则**：

- 卡可以规定角色的 commitment：**“我必须尝试把它交给她 / 我不能没说就离开”**；
- 卡不能规定玩家行为：**“她必须收下”**；
- 如果正典要求最终物件确实落到玩家手里，那必须由**世界/脊柱合同**表达，不该伪装成角色心理指令。

这处需要 ★★★ 人裁，见 §11。

---

### 2.8 Context / Knowledge：分层已经存在，但“唯一装配入口”还没真正成立

已有：

- `context_assembly.py` 明确 stable / present / scene window / goal memory 四层；
- Knowledge schedule、KGE、disclosure、memory activation 都有。

差距：

- `context_assembly` 当前 `enforcement="observe_only"`；
- ActorPacket 的真实构造仍由 `free_stage_prototype.build_actor_context_packet()` 这个大函数完成；
- DB knowledge、card knowledge_gate、persona disclosure 有多路补丁式合并。

目标：

> ActorContextAssembler 成为唯一 ActorPacket 入口；观测台看到的 assembly receipt 与真正送给模型的包来自同一次构造。

## 3. 根因分类：设计债 vs 实现债

### 3.1 设计债

必须先裁清，否则代码会继续左右互搏：

1. ★★★ **挂坠固定事实的粒度**
   是“龙也必须完成赠与尝试”，还是“玩家最终必须取得挂坠”？
2. Storylet MH 是否允许表达“对方必须接受”的事实？
   若允许，必须明确由世界因果实现，而不是 NPC stage 强制。
3. ActorMind 的关系 / affect 是否要作为当前阶段的唯一动态关系权威。
   本计划建议“是”，但全书量产可后置；竖切先做。

### 3.2 实现债

不需创意人裁，可直接工程重构：

- `free_stage_prototype.py` 过度集中；
- `private_inner_states` 与 ActorMind 双轨；
- 直接写 `completed` 的路径过多；
- 世界事件不是统一 receipt；
- Exit 与 MH 耦合；
- scene-specific 规则散落主循环；
- Player Agency 保护器没有抽象为全局协议；
- ContextAssembly 只是观察器；
- quick 中核心新架构验证仍有缺口。

## 4. 重构原则

### R1 · 先减少权威，再减少代码

不是先把 13k 行拆成 20 个文件。

如果只是搬文件、不改“谁能写什么”，只是把意大利面切成短一点的意大利面。

第一目标是：

> 每个状态字段都能回答：**谁是唯一 writer？**

---

### R2 · 事件先于状态

禁止随手：

```python
completed.append("RP4")
player_state["item"] = ...
actor_mind["trust"] += 1
```

目标统一成：

```text
Observation
→ Decision / PlayerAction
→ Resolver
→ EventReceipt
→ Reducers
   ├ world reducer
   ├ beat reducer
   ├ actor mind reducer
   └ exit reducer
```

状态是事件投影，不是各模块共享的白板。

---

### R3 · LLM 只能提议 / 演绎，不能落事实

- Actor LLM：提出自己的 decision + 演出；
- Director LLM：从合法世界机会中选/填；
- Memory LLM：可以总结，但写入前有 provenance / reducer；
- 所有世界事实、玩家行为、MH、关系数值变化都由确定性 Resolver 决定。

---

### R4 · 角色可以被世界逼，但不能被导演代写

导演可以：

- 下雨更大；
- 店要关门；
- 路人进来；
- 时间窗缩短；
- 门被锁；
- 警报响。

然后角色自己决定怎么办。

导演不能：

- “龙也现在必须说托付”；
- “秋人现在必须借视频”；
- “玩家已经接过挂坠”。

---

### R5 · 兼容层必须有死亡日期

本轮允许保留 bridge，但每一条 bridge 必须写：

- source；
- target；
- removal milestone。

禁止无限期“双轨都留着”。

---

## 5. 目标模块边界

建议不是一次重写整仓，而是把现有模块重新排成这几层：

```text
runtime/
  engine/
    turn_engine.py            # 一拍 orchestration，只排顺序，不写剧情特例
    observation.py            # 公共/私有可见性
    event_protocol.py         # Event / Receipt 统一协议
    reducers.py               # world/beat/player/actor/exit reducers
    exit_policy.py            # 唯一关场入口

  actors/
    context_assembler.py      # ActorPacket 唯一装配入口
    mind.py                   # ActorMind reducer
    deliberation.py           # concern / participation intent
    enactment.py              # LLM actor call
    reflection.py             # reflection proposal -> mind receipt

  director/
    harness.py                # 闭集 world opportunity
    ports.py                  # Stage / Dramaturgy / Voice / Resolver
    policy.py                 # 合法招判定，不碰角色心理

  storylets/
    beat_state.py             # MH stage projection
    policies/
      ryuya_prologue.py       # 咖啡馆纯场策略
      tiananmen.py
      c16_gate.py

  projections/
    observer.py
    save_state.py
```

这只是**职责目标**，不要求第一刀就改成这些目录名。

## 6. 新主循环目标

```text
TurnEngine.step(input)

A. ingest
   parse modalities
   append raw player event
   derive public/private observations

B. resolve player-owned effects
   PlayerActionResolver
   → player receipts
   → reducers

C. observe world
   stage public facts
   current storylet beat states
   actor-specific observable slices

D. actor deliberation
   each present actor:
       context = assemble()
       intent = deliberate()
   intents do not yet speak

E. arbitration
   floor manager selects speak order
   companion lanes select visible backchannel
   director selects legal world opportunity

F. enact
   selected actors enact
   director Stage/Voice enact

G. resolve visible outputs
   Resolver validates:
       player agency
       body continuity
       knowledge / spoiler
       world effects
       beat evidence
   create EventReceipts

H. reduce
   WorldStateReducer
   BeatStateReducer
   ActorMindReducer
   BodyReducer
   ExitReducer

I. reflect
   actor reflection proposals from actual receipts
   → ActorMind receipt only

J. project/save
   observer projection
   session snapshot
```

关键约束：

- `TurnEngine` 不出现“张尘”“挂坠”“天安门”等业务词；
- scene policy 可以知道业务词，但不能直接改全局状态；
- reducer 不调用 LLM；
- observer 不参与生产决策。

## 7. 分阶段迁移

### Phase 0 · 冻结与测绘

**目标**：先知道谁在写什么，不再盲拆。

做：

- 建 `runtime authority map` 测试/文档：
  - `completed`
  - `branch_progress`
  - `world_transactions`
  - `player_state`
  - `body_frames`
  - `private_inner_states`
  - `actor_minds`
  - `fsm_by_cons`
  - `rel_state_by_cons`
  - `ended`
- 搜所有直接 writer；
- 标记 producer / reducer / projection；
- 给 `FreeStageSession.step()` 写 characterization tests，冻结当前两场好行为。

**验收**：

- 不改体验；
- quick 绿；
- 能生成“每个关键字段有几个 writer”的机器报告。

---

### Phase 1 · Exit 权威收口

**为什么先做**：这是风险最低、收益最高、a14 已证明的问题。

做：

- 新 `ExitPolicy`；
- 所有关场只经 `exit_policy.resolve(...)`；
- 删除 generic “MH 齐 + 无 exits = EndRun”默认；
- 默认 `auto_end_on_complete=false`；
- 纯过场显式 opt-in；
- transition / EndRun 各自返回 receipt。

**验收**：

- RP/MH complete 不自动结束社交场；
- 明确玩家离场才关咖啡馆；
- canonical auto transition 场仍能按声明自动走；
- EndRun 幂等。

---

### Phase 2 · BeatState + Player Agency 收口

**目标**：先把“发生没发生”从 prompt /动作散文里拿回来。

做：

- 引入 `BeatState`：
  - `unseen`
  - `open/offered`（可选）
  - `settled`
- `completed` 变成只读兼容投影；
- 所有 MH 变化经 `BeatReceipt`；
- 引入 `PlayerActionReceipt`；
- 全局 player-agency validator：
  - possession
  - movement
  - promise/acceptance
  - relationship choice
  - irreversible action
- 咖啡馆挂坠作为第一竖切。

**验收**：

- 模型 stage 永远不能单方面让玩家获得/失去关键物；
- 模糊台词不能自动 accepted；
- RP4 的内部两阶段在 observer 可见；
- 旧 `completed` UI 仍正常。

---

### Phase 3 · ActorMind 真权威

**目标**：去掉“双脑”。

做：

- ActorMind 增加最小动态 facet：
  - active_goals
  - commitments
  - appraisal
  - relation state
  - affect tag（先枚举/薄，不做复杂情绪引擎）
- `private_inner_states` 改为 **TurnWorkingContext**，不再作为持久真值；
- save 时只保存 ActorMind + 必要 projection；
- 下一拍 working context 从 ActorMind + scene observation 重新装；
- Reflect 不再只是自由文本回灌：
  - reflection proposal
  - deterministic validate
  - MindReceipt
  - reducer apply
- FSM / RelState 先作为 ActorMind facet 或 projection bridge，禁止继续独立生长。

**迁移**：

- 旧存档读到 `private_inner_states` 时做一次 adapter；
- adapter 只提取可证明字段，不把自由散文升级为永久人格事实。

**验收**：

- ActorPacket 的持续心理状态只来自 ActorMind；
- observer 中 `authority=actor_mind` 不再只是标签；
- 同一事件不会同时改 ActorMind + private_inner_states 两份权威。

---

### Phase 4 · Actor participation ownership

**目标**：落实 2026-08-04 已裁的社交宪法。

做：

1. 所有在场 Actor 先产生轻量 `ParticipationIntent`：
   - speak
   - backchannel
   - side
   - pass
   - urgency / addressee / concern_id
2. Floor manager 只仲裁冲突：
   - direct addressee 优先；
   - adjacency obligation；
   - 物理卷入；
   - fairness / recent floor；
   - 不做内容 boost。
3. 获得 floor 后才 Enact。
4. 被裁掉的 speak 意图保持 concern，不算失败。

**性能约束**：

- 不一定给每人多打一遍昂贵 LLM。
- 第一版可由结构化 ActorMind + deterministic deliberation 产 intent；
- 只有真正拿到 floor 的 actor 才调用 Enact LLM。

**验收**：

- “谁说话”与“说什么”真正分离；
- 无 `natural_video_ask +0.55` 一类内容加分；
- pass 是合法成功输出，不被系统强行补台词。

## 8. 咖啡馆作为重构竖切

为什么仍选咖啡馆：

- 单角色，能先隔离 ActorMind 与 Director；
- 有熟人闲聊；
- 有语义转认真；
- 有托付；
- 有物件；
- 有玩家接受/拒绝权；
- 有离场；
- 有 run / EndRun / scar；
- a14 已有真实 badcase。

### 竖切成功标准

一局里必须能自然出现：

1. 玩家一直玩笑 → 龙也可以等，不因拍数强推；
2. 玩家主动打开认真接口 → 龙也自己转正事；
3. 托付必须真的说出口，stage 不算；
4. 挂坠必须明确提出赠与；
5. 玩家可以收 / 拒 / 暂放 / 不理；
6. 龙也必须尊重处分，不重复递、不替玩家拿；
7. RP 全完成后还能继续聊；
8. 只有真正离场才 EndRun；
9. 第二周目环境可有 scar，但龙也不知道“上一周目”；
10. ActorMind 的下一拍状态能解释上一拍实际 receipt，而不是 prompt 临时编的心理。

## 9. 验证策略重做

### 9.1 quick 不追求数量，追求权威不变量

新增五类核心闸：

#### A. Authority tests

- ActorMind 是唯一 persistent mental writer；
- BeatState 只有 BeatReducer 可写；
- EndRun 只有 ExitPolicy 可写；
- key item custody 只有 World/PlayerAction reducer 可写。

#### B. Replay tests

给定：

- session snapshot
- player input
- actor deterministic fixture
- director deterministic fixture

应得到完全一致的：

- receipts
- BeatState
- ActorMind state
- world transaction
- exit result。

#### C. Cross-layer contradiction tests

专门防：

- card 要求玩家做 X，但 PlayerAgency 不允许；
- MH done 但 receipt 不存在；
- ActorMind 说 accepted 但 world item 未转移；
- observer 显示状态与 prompt 实际状态不同。

#### D. Human-feel regression fixtures

从 play_logs 把真实 badcase 变 fixture：

- `a14` 假断线；
- RP4 自动关场；
- 挂坠动作代替语言；
- 模糊回应被当 accepted；
- “你最好有事情”被误当 serious invitation。

#### E. Architecture checks

机器扫描：

- core TurnEngine 中不得出现 scene-specific business ids；
- 禁止新增 `self.completed.append(...)` 绕 BeatReducer；
- 禁止新增 `self.ended=True` 绕 ExitPolicy；
- 禁止 Actor LLM 输出直接落 world state。

## 11. ★★★ 唯一需要先人裁的内容问题：挂坠固定底粒度

当前卡写法与 Player Agency 新合同冲突。

请裁一个：

### 方案 A · 固定“赠与尝试”

正典固定：

> 龙也临别前必须明确告诉玩家挂坠是给她的，并当面递出。

玩家可：

- 收下；
- 拒绝；
- 暂放；
- 不回应。

若本周目没收，未来由世界因果决定它是否再次出现。

**优点**：玩家 agency 最完整；角色 commitment 与玩家结果分开。
**代价**：如果原著/总体结构要求玩家必持挂坠，后续因果需要另找合法路径。

### 方案 B · 固定“最终取得挂坠”

正典固定：

> 本节点结束前，玩家必须实际取得挂坠。

但实现不能靠龙也替玩家接。

如果玩家拒绝，必须由**后续可见世界事件 / 新路径**满足固定事实，例如遗留、转交、误放入物件等，而且所有合法路径需要有正典/人裁来源。

**优点**：维持“玩家必得关键物”的剧情固定底。
**代价**：自由度更低，需要明确的合法因果路径，不能靠 stage 强塞。

**本计划不代裁。**

在裁决前，运行时临时按最保守的 Player Agency 口径：

> 龙也可提出，玩家不明确接受则不写 custody。

## 14. 本重构完成的判据

不是“文件更漂亮”。

而是能回答下面十个问题，而且每题只有一个答案：

1. 角色现在想什么？→ ActorMind
2. 角色知道什么？→ ContextAssembler + Knowledge authority
3. 谁现在想说话？→ Actor deliberation
4. 谁实际获得 floor？→ Floor arbitration
5. 导演能做什么？→ Director closed world opportunities
6. 这件事真的发生了吗？→ EventReceipt / Resolver
7. 玩家是否做了这个动作？→ PlayerActionReceipt
8. MH 到哪一步？→ BeatState reducer
9. 场能不能结束？→ ExitPolicy
10. 下周目留下什么？→ EndRun settle / sediment

如果任一题有两个模块都能回答，重构就还没完成。
